# 11. 風險與技術債

## 11.1 技術債
- **硬編碼配置**：標準上班時間 (09:00) 目前硬編碼在 `attendance.py` 與 `utils.py` 中，應移至資料庫 `system_settings` 管理。 <!-- TODO: 需調整為動態設定 -->
- **錯誤處理**：目前的 `chat.py` 對於 Gemini API 失敗的處理較為簡單，缺乏重試機制。
- **前端測試**：目前缺乏自動化單元測試 (Vitest) 與端到端測試 (Cypress)。

## 11.2 風險
- **地圖隱私**：打卡座標儲存於資料庫，需確保資料存取權限嚴格控管。
- **Gemini API 額度**：過度頻繁的對話可能導致 API 費用超標或達到 Rate Limit。
- **資料庫遷移**：目前主要依賴啟動時的 `create_all`，缺乏正式的 Alembic 遷移管理，這在未來 schema 變更時會有風險。 <!-- TODO: 建議導入 Alembic -->
